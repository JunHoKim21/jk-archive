AI 한 명이 다 짜지 않고 팀장(오케스트레이터)과 팀원(워커)으로 나눠 코딩 테스트해 본 후기

1. AI도 혼자 다 하기보다 팀으로 일하면 어떨까?​

보통 AI에게 코딩이나 작업을 맡길 때는 AI 한 명에게 모든 일을 한꺼번에 요청하곤 합니다. 하지만 만들어야 할 파일이 늘어나고 기능이 복잡해지면, AI 혼자 여러 파일을 오가다가 앞의 내용을 잊어버리거나 방금 고친 코드를 실수로 덮어쓰는 일이 생길 수 있습니다. 그래서 이번에는 AI 한 명에게 모든 코드를 맡기지 않고, 실제 회사에서 팀이 협업하는 것처럼 역할을 둘로 나누어 테스트해 보았습니다.

  • 팀장 AI (오케스트레이터): 전체 흐름을 설계하고 작업을 나눈 뒤, 마지막에 결과물을 직접 검수하는 역할입니다. (직접 코드를 작성하거나 수정하지 않습니다.)
  • 작업자 AI (워커): 팀장 AI가 지정해 준 파일만 맡아서 실제 코드를 작성하고 수정하는 실무 담당입니다.

2. 왜 굳이 역할을 나눠서 시킬까?​

작업을 쪼개서 위임하는 방식에는 크게 두 가지 장점이 있습니다.

  • 병렬 처리(속도 향상): 서로 관련이 없는 작업은 한 작업이 끝날 때까지 기다릴 필요 없이, 여러 작업자 AI에게 동시에 맡겨 빠르게 처리할 수 있습니다.
  • 소유권 분리(안전성 확보): 각 작업자 AI마다 수정할 수 있는 파일 범위를 엄격히 제한해 둡니다. 내가 맡은 파일 밖은 건드리지 못하게 선을 그어 두기 때문에, 다른 작업자가 작성한 코드를 실수로 덮어쓰는 사고를 원천적으로 막을 수 있습니다.

그림 1. 팀장 AI(오케스트레이터)가 작업을 병렬·순차 그룹으로 나누어 위임하고 최종 검수하는 전체 구조

3. 테스트 ①: 병렬 작업 + 순차 작업 + 자동 통합 테스트​

기존 프로젝트 코드에 전혀 영향을 주지 않기 위해, 독립된 실험 폴더(orchestrator-test)를 만들고 Node.js에 기본으로 내장된 자동 테스트 도구(node --test)를 사용해 첫 번째 테스트를 진행했습니다. 이번 미션에서 만들어야 할 대상 파일은 총 4개였습니다.

파일 경로 역할 주요 기능

orchestrator-test/mathUtils.mjs 숫자 계산 도구 합계(sum), 평균(average) 계산

orchestrator-test/textUtils.mjs 문장 다듬기 도구 URL 슬러그 변환(slugify), 글자 자르기(truncate)

orchestrator-test/summary.mjs 최종 요약 생성 위 두 파일을 불러와 요약 객체 생성

orchestrator-test/summary.test.mjs 자동 품질 검사 전체 동작이 올바른지 자동으로 검증

(참고: slugify는 웹 주소(URL)에 쓰기 좋게 문장을 깔끔한 형태로 다듬는 기능이고, truncate는 긴 문장을 정해진 길이에 맞춰 잘라 주는 기능입니다.) 팀장 AI는 각 파일이 서로 연결되어 있는지를 살펴보고, 작업 순서를 3단계로 나누어 지시했습니다.

  1. 1단계(병렬 작업): 서로 독립적인 mathUtils.mjs와 textUtils.mjs를 2명의 작업자 AI가 동시에 작성했습니다.
  2. 2단계(순차 작업): 앞선 두 파일이 모두 완료된 것을 확인한 뒤, 두 도구를 불러와 합치는 summary.mjs를 작성했습니다.
  3. 3단계(순차 작업 + 최종 검수): 구현이 끝난 뒤 summary.test.mjs 테스트 파일을 작성하고, 마지막으로 팀장 AI가 직접 node --test를 실행해 20개 테스트 전부 통과(실패 0건)를 확인했습니다.

그림 2. 실제 실행 화면: Wave 1(mathUtils.mjs, textUtils.mjs) 완료 확인 후 Wave 2(summary.mjs)와 Wave 3(summary.test.mjs)를 순차 위임하는 모습

4. 테스트 ②: 같은 파일에 기능 2개를 추가할 때 충돌 막기​

두 번째는 실무에서 자주 마주치는 까다로운 상황을 가정한 테스트였습니다. 이미 만들어 둔 orchestrator-test/summary.mjs 파일 하나에 아래 두 가지 기능을 모두 추가하는 미션이었습니다.

  1. 최솟값(min)과 최댓값(max)을 함께 구해 주는 기능 추가
  2. 평균 값을 기준으로 A, B, C 등급(grade)을 계산해 주는 기능 추가

만약 이때 작업자 2명에게 "둘 다 지금 바로 summary.mjs를 고쳐!"라고 동시에 지시하면 어떻게 될까요? 두 사람이 같은 문서 파일을 동시에 열어 각자 고치고 저장하는 것과 똑같이, 나중에 저장한 쪽이 앞사람의 수정 내용을 덮어써 버리는 충돌이 발생합니다. 그래서 팀장 AI는 이번 작업을 병렬이 아닌 순차 지시로 처리했습니다. 같은 파일의 담당 작업자 AI에게 1단계(min/max 추가 및 완료 확인) → 2단계(grade 계산 추가 및 완료 확인) → 3단계(summary.test.mjs 테스트 보강) 순서로 한 번에 한 가지 작업만 맡긴 것입니다.

그림 3. 같은 파일(summary.mjs) 수정 시 동시 수정 충돌을 피하기 위해 순차 지시로 안전하게 처리한 비교 흐름 앞선 수정이 완전히 끝난 것을 확인한 뒤에 다음 기능을 얹었기 때문에 코드가 꼬이거나 덮어써지는 문제가 전혀 발생하지 않았습니다. 테스트 보강 후 팀장 AI가 node --test를 다시 실행해 본 결과, 기존 20개에 새 기능 검증이 더해진 22개 테스트가 실패 없이 전부 통과(실패 0건)했습니다.

5. 이번 테스트로 확인한 핵심 정리 3가지​

    1. 팀장 AI는 직접 코드를 고치지 않고 작업자 AI에게 위임합니다. 계획을 세우고 파일을 나누며 최종 결과를 검증하는 데 집중하고, 실제 코드 수정은 파일 소유권이 명확히 나뉜 작업자에게 맡깁니다.
    1. 안 겹치는 일은 병렬로 빠르게, 같은 파일이나 의존성 있는 일은 순차로 안전하게 처리합니다. 무조건 동시에 실행하는 것이 답은 아니며, 파일이 겹치거나 앞선 작업 결과가 필요한 경우에는 순서를 지켜 충돌을 예방합니다.
    1. 마지막 문법 검사와 통합 테스트는 직접 실행해 결과를 확인합니다. 작업자의 완료 보고만 믿고 끝내지 않고, 팀장 AI가 직접 테스트 도구(node --test)를 실행해 실제 통과 여부를 확인합니다.

6. 한 줄 결론​

AI와 협업할 때도 겹치지 않는 일은 동시에 맡겨 속도를 높이고, 같은 파일이나 연결된 일은 순서를 지켜 안전하게 합친 뒤, 마지막은 직접 실행한 테스트로 검증하는 팀 구조가 훨씬 안정적이고 믿을 수 있는 결과를 만들어 줍니다.

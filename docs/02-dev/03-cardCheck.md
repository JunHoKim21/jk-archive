> **"카드사 앱들의 무거운 로그인과 로딩 피로감 없이, 결제하는 즉시 삼성페이와 푸시 알림을 가로채 이번 달 30만 원 실적 달성률을 1초 만에 확인할 수는 없을까?"**

월간 카드 혜택을 챙기기 위해 매달 채워야 하는 전월 실적(30만 원, 50만 원 등). 하지만 여러 카드사 앱을 일일이 로그인해 확인하는 것은 번거롭고, 유료 SMS 알림 서비스(월 300원)나 클라우드 마이데이터 API는 비용 및 개인정보 노출 부담이 따릅니다.

15년 차 백엔드 개발자로서 AI 코딩 에이전트와 페어 프로그래밍을 진행하여, **외부 서버 통신 0원 & 100% 오프라인 로컬 환경**에서 삼성월렛(삼성페이)·카드사 푸시·문자 알림을 실시간 감지해 실적을 자동 집계하는 Android 네이티브 앱 **『카드실적』**을 개발한 과정과 핵심 트러블슈팅을 정리합니다.

---

## 1. 프로젝트 개요 & 아키텍처

* **서비스명**: 카드실적 (`JunCardTracker`)
* **핵심 컨셉**: 무거운 카드사 앱 접속 없이 결제 즉시 상단바 알림을 감지하여 목표 실적 달성률을 추적하는 초경량 안드로이드 유틸리티
* **운영 형태**: 스마트폰 내부 SQLite에만 데이터를 암호화/저장하는 완전 로컬 독립 실행형 네이티브 앱

### 🛠️ 기술 스택 상세

| 영역 | 기술 스택 및 버전 | 핵심 역할 |
| :--- | :--- | :--- |
| **Platform & Core** | Android Native (Kotlin 2.3.20, JVM 17, `targetSdk = 35`) | 네이티브 모바일 애플리케이션 코어 |
| **UI Framework** | Jetpack Compose (1.10.6), Compose Material 3 (1.4.0) | 선언형 UI, 동적 게이지 차트, 반응형 바텀시트 모달 |
| **Architecture** | MVVM + Repository Pattern + Reactive Stream | `StateFlow`, Kotlin Coroutines 기반 단방향 데이터 흐름 |
| **Database** | Android 내장 SQLite (`SQLiteOpenHelper` 직접 구현) | KSP/Room 컴파일 오버헤드 배제 및 빠른 영속성 보장 |
| **System Service** | `NotificationListenerService`, `BroadcastReceiver` | 시스템 상단바 알림 가로채기, 앱 미실행 무음 분류 처리 |
| **Build & CI** | Gradle 9.3.1 Wrapper | 자동 빌드 및 디버그 APK 자동 산출 파이프라인 |

## 2. 기술적 차별점 3가지

### ① 월 비용 0원 & 완전 로컬 데이터 격리 (Zero Cloud, Zero Cost)
* 외부 서버, 클라우드 DB, 금융 마이데이터 API를 전혀 사용하지 않습니다.
* 모든 결제 내역과 실적 데이터는 스마트폰 내부 SQLite에만 격리 보관되므로, 금융 개인정보 유출 위험이 원천 차단됩니다.

### ② 오프라인 100% 동작 & 네트워크 무의존성
* 데이터 통신이 끊긴 비행기 모드나 지하, 통신 장애 상황에서도 스마트폰 내부 로컬 알림 리스너와 SQLite가 동작하므로 100% 정상 작동합니다.

### ③ 유료 문자 비용을 아끼는 '하이브리드 알림 감지 전략'
* **NH농협카드**: 무료 앱푸시를 감지해 해당 카드로 즉시 자동 합산.
* **삼성/롯데카드 (5만 원 이상)**: 카드사 무료 앱푸시/문자를 자동 인식하여 즉시 합산.
* **삼성/롯데카드 (5만 원 미만 소액)**: 무료 푸시가 오지 않는 카드사 특성을 고려해, **삼성페이 결제 알림**을 감지한 후 상단바에 `[삼성]` / `[롯데]` 원터치 선택 버튼을 띄워 앱을 켜지 않고도 1초 만에 분류 완료.

## 3. 핵심 기능 및 엔지니어링 구현 로직

### 1) 실시간 결제 알림 감지 및 이중 합산 방지 파이프라인
* **관련 모듈**: `CardNotificationListenerService.kt`
* `NotificationListenerService`를 상속받아 등록된 패키지(`com.samsung.android.spay`, NH Pay, 카드사 앱, 기본 메시지 앱)의 결제 알림을 후킹합니다.
* **중복 방지 큐(5초 디바운스)**:
  * 삼성페이 결제 시 삼성페이 자체 알림과 카드사 알림이 연달아 발생하는 경우가 있습니다.
  * 카드사 식별 알림이 도착했을 때, **직전 5초 이내에 동일 금액의 삼성페이 미분류 알림이 대기 중이었다면 해당 대기 작업을 취소**하여 중복 합산을 원천 방지합니다.

### 2) 앱 미실행 상태바 원터치 분류 (`BroadcastReceiver`)
* 삼성페이 소액 결제 감지 시 상단 상태바에 다음과 같은 액션 알림을 발행합니다:
  > **💳 삼성페이 1,300원 결제 감지 (롯데 프리미엄 푸드마켓)**  
  > `[삼성카드]` `[롯데카드]` `[무시]`
* 사용자가 앱을 켜지 않고 상단바에서 카드 버튼을 한 번 터치하면, `CardAssignActionReceiver`가 백그라운드에서 SQLite에 즉시 반영하고 알림을 닫아 사용자 액션을 최소화합니다.

### 3) 동적 실적 산정 기간 및 달성률 계산 (`PerformanceCalculator`)
* 카드사마다 서로 다른 실적 인정 기준일(`billingDay`: 1~28일)을 완벽 지원합니다:
  * **기준일 1일**: 당월 1일 ~ 말일 자동 계산 (예: `11.01 ~ 11.30`)
  * **기준일 N일**: 전월 N일 ~ 당월 N-1일 산정 기간 동적 반환
* 목표 금액 대비 인정 누적 실적, 잔여 금액(`remainingAmount`), 달성률(`progressPercent`: 0~100%), 달성 여부(`isAchieved`)를 1원 단위 오차 없이 실시간 계산합니다.

### 4) 자동 제외 키워드 필터링 & 수동 보정 기능
* 가맹점명에 사용자가 사전 정의한 실적 제외 키워드(`관리비`, `국세`, `지방세`, `상품권`, `무이자` 등)가 포함되어 있으면 자동으로 `included = false` 처리하고 제외 사유를 기록합니다.
* 월 중간에 앱을 설치한 경우를 대비해, 카드별 `[보정]` 버튼을 통해 기존 누적 실적을 즉시 가감(`manualAdjustment`)할 수 있는 바텀시트를 제공합니다.

### 5) 비정형 영수증 텍스트 일괄 등록 (`BulkTextParser`)
* 과거 승인 내역 문자나 영수증 내역 여러 줄을 복사/붙여넣기 하면 정규식 기반으로 자동 파싱합니다:
  * 날짜 헤더(`11월 16일`), 가맹점명(`(주)비케이알` 등 괄호 보존), 통화 기호(`₩8,990`), 12/24시간제 시각(`오후 8:54` ➔ `20:54`) 자동 정제.
  * `skipDuplicates` 옵션으로 동일 카드·시각·가맹점·금액 데이터가 이미 존재할 경우 중복 등록을 자동 방지합니다.

## 4. 실전 트러블슈팅 기록

### 🔥 Issue 1. 실제 결제 시 삼성페이 알림 미감지 버그
* **현상**: 실제 매장에서 스마트폰으로 결제 시 상단바에 알림(`₩1,300 결제 완료`)이 발생했으나 앱이 결제를 인식하지 못함.
* **Root Cause**:
  * 기존 파서 정규식이 `([0-9,]+)\s*원` 형태로 선언되어 있어, 숫자 뒤에 반드시 '원'이 붙어야만 금액으로 파싱했음.
  * 실제 삼성월렛(삼성페이) 푸시 알림의 Title은 `₩1,300 결제 완료  오후 12:20` 형태로, 숫자 앞단에 원화 기호(`₩`, `\u20A9`)만 있고 뒤에 '원'이 붙지 않는 구조였음.
* **해결**:
  ```kotlin
  // 전치(₩1,300) 및 후치(1,300원) 원화 표기 모두 지원하도록 정규식 전면 개편
  val AMOUNT_REGEX = Regex("""(?:[₩￦\u20A9\uFFE6]\s*([0-9]{1,3}(?:,[0-9]{3})+|[0-9]{3,})|([0-9]{1,3}(?:,[0-9]{3})+|[0-9]{3,})\s*(?:원|[₩￦\u20A9\uFFE6]))""")
  ```
  * 가맹점명 추출 시에도 텍스트에 단독 표기된 가맹점을 최우선 파싱하도록 `extractMerchant` 로직을 정밀화하고 단위 테스트를 추가해 해결했습니다.

### 🔥 Issue 2. ORM 의존성 배제 및 표준 SQLite 채택
* **현상**: KSP/Room 라이브러리 연동 시 Kotlin 2.x 버전과의 컴파일러 플러그인 호환성 이슈 및 빌드 타임 증가 우려 발생.
* **해결**: 순수 Android 내장 `SQLiteOpenHelper`로 영속 계층을 직접 구현하여, 외부 라이브러리 충돌 가능성을 원천 차단하고 빌드 속도를 대폭 단축했습니다.

## 6. 한계점 및 향후 과제

1. **할인 적용 건의 실적 제외 한계**:
   * 개인 개발자는 금융 마이데이터 API 발급이 불가능하므로, 카드사 알림에 별도 표기되지 않는 '청구할인 등으로 인한 실적 미인정 건'은 키워드 필터와 수동 토글 스위치에 의존합니다.
2. **One UI 배터리 절전 정책 예외 설정 필요**:
   * 백그라운드에서 알림 리스너가 절전 모드로 강제 종료되지 않도록 최초 1회 **'배터리 사용량 제한 없음'** 및 **'알림 접근 권한'**을 사용자가 켜주어야 합니다.
3. **삼성페이 소액 결제의 1회 원터치 개입**:
   * 삼성/롯데 소액 결제 시 상단바에서 카드 버튼을 한 번 눌러주는 최소한의 사용자 액션이 필요합니다.
